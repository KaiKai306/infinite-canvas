# HappyKai 定制与维护

基于 `tigerowo/infinite-canvas`，保留上游界面、生成逻辑及 Canvas Agent。使用 SQLite、私有 R2，不自动创建或读取 New API 模型令牌。

## 账号

- 设置 `NEW_API_BASE_URL` 后，普通登录通过服务端 HTTP 验证 New API 密码，完成后再次读取 `/api/user/self`。支持旧版 Cookie、新版 Bearer 登录及 TOTP。验证码挑战仅保存在内存，五分钟过期、一次尝试，失败需重新登录。暂不支持 Passkey、OAuth，或启用 Turnstile、强制密码加密后的流程。
- `newapi-<数字用户ID>` 作为本站 ID 和内部用户名，显示名来自 New API。不会按昵称、邮箱合并账号。不要将同一数据库切换到另一套 New API 实例。
- New API `role >= 100` 映射为管理员，其余为普通用户。管理员从网页账户菜单进入 `/admin`。另保留本地恢复管理员，通过 `/api/admin/login` 使用独立密码。
- 关闭本站注册和 Linux.do 登录；首次成功的 New API 登录创建本站映射。后台注册开关不能覆盖环境配置。
- Canvas 会话独立有效八小时（Compose 配置）。New API 禁用账号、改密或降权不会即时撤销 Canvas 会话；下次登录重新检查。紧急禁用请同时在 Canvas 后台禁用账号。退出会清除浏览器文件 Cookie；已复制的 Bearer JWT 仍有效到过期或本站禁用。
- 浏览器 IndexedDB、模型配置、用户存储配置按账号分区；登录/退出整页加载，其他标签切换账号时重新加载，避免前一账号或游客缓存混入新账号。游客内容需手动导出、导入。缓存分区不是加密，共用电脑应使用独立浏览器配置。

## 存储与下载

- 文件信息/内容仅所有者或管理员可读。写入 API 仍要求 Bearer；图片 GET 使用 Secure、HttpOnly、SameSite=Lax Cookie，恢复登录时刷新，有效期不超过原 JWT。
- 私有 Standard 桶 `happykai-canvas-media`，不设置 `publicBaseUrl`。上传为 `浏览器 → 186 → R2`，预览/下载为 `R2 → 186 → 浏览器`，会使用 186 带宽。支持 Range，禁止共享缓存。不需要公共桶域名及浏览器 CORS。
- 186 上 SQLite 保存账号、画布 JSON、素材索引和配置，媒体原文件在 R2；浏览器保留缓存。数据库、日志和备份仍需常规运维。
- 登录后保存模型配置会沿用上游行为，将手工填写的模型渠道 Key 同步到 SQLite；并非只存在浏览器。New API 登录密码和临时登录会话不写入本站数据库。
- Caddy 拒绝匿名上传接口，游客本地保存，避免使用上游临时文件托管。

## 部署与升级

1. 创建桶及仅此桶 Object Read & Write 令牌，在服务器交互终端运行 `python3 /srv/infinite-canvas/configure.py`。不在命令行参数、聊天或 Git 填写密钥；`.env` 权限 0600。
2. 隔离构建并验证 Go 测试、类型检查、上游 Docker 构建，用具体镜像标签运行 Compose，端口只绑定 `127.0.0.1:13800`。连接已有 `new-api_default` 网络，不重启 New API。
3. 通过原生管理设置配置全局 R2 并启用登录账号同步。模型 Key 由用户自行填写。R2 凭据保存在上游 SQLite 私有设置中，须保护数据库、配置和备份。
4. 备份、验证 Caddy 配置并重载，核实 HTTPS、账号和文件权限。撤回只停止本站 Compose、移除本站路由；是否删除数据库和桶另行确认。

后续在独立分支合并上游，重点检查登录适配、文件鉴权、浏览器缓存分区。完成相同验证再生成新镜像；保留升级前 SQLite 一致性备份及旧镜像，表结构变化时用配套数据库备份回滚。

本次 Go 测试/vet、前端/最终镜像构建、真实 R2 读写删除、浏览器游客/两账号隔离及清缓存后的云端恢复通过。完整 TypeScript 检查有 17 个上游既有错误，没有新增错误；上游构建配置原本跳过类型错误。真实 New API 密码登录已由用户确认，模型调用及本地 Codex 连接仍需实际用户验收。

DNS 托管在阿里云，A 记录指向 186。Caddy 自动签发和续期证书；系统解析器缓存旧 A 记录时，路由脚本可用 `--dns-server 1.1.1.1` 指定已核对的解析器，不修改服务器全局 DNS。

## 界面推广清理

移除顶部/404 公告、首页中转站轮播及提示词站推广、用户/管理配置中的第三方登录与获取 Key 推广入口，以及邀请返利链接。首页保留四张无外链的功能轮播。模型协议适配继续使用上游实现。README 保留原项目与 AGPL 署名，页面 GitHub 入口指向此 fork 的 `happykai` 分支，提供本实例对应源码。

本地 Codex 沿用 `canvas-agent/README.md` 的上游插件或 MCP，在电脑本地运行服务并连接本站画布，无需额外维护连接功能分支。插件操作浏览器当前账号，连接 Token 不要分享。

站点显示名为 `Kai's 无限画布`。首个个人渠道在无已有配置时默认使用 `https://api.happykai.cn`，不覆盖既有渠道、地址或 Key；新增其他渠道仍沿用各协议默认地址。“个人渠道 / 站点渠道”描述模型凭据来源，不表示保存位置。接口高级选项保留上游配置字段，仅整理入口与说明。

游客的常规图片请求为浏览器 → 本人模型渠道，需要渠道允许 CORS；结果、画布和配置在当前浏览器，关页可能中断，不使用本站账号归档。游客内容不会在登录时自动合并，需先导出再导入。登录后的图片任务为浏览器 → 186 → 本人渠道 → 186 → R2；画布操作期间网页应打开，已提交的服务端图片请求可继续处理。

后台区分模型权限与存储权限；New API 登录模式下本站独立注册开关不可用。`/api/storage/config` 额外公开 `serverImageArchive` 布尔运行标志，不包含凭据。“素材自动同步”不关闭独立启用的图片任务归档，也不承诺独立音视频工作流断页后完成存储。详细本地 Codex 操作见 [CODEX.md](CODEX.md)。

## 个人渠道与云端数据边界

当前版本登录后，即使界面选“本地直连渠道”，图片请求也使用本站后端和本人保存的渠道 Key，画布/生图工作台可创建服务端图片任务；未登录时才使用浏览器直连路径。“云端渠道”主要指管理员配置的渠道，并非区分本机 GPU 和远程模型。

登录打开画布会读取远端账号数据，并与该账号的本地缓存合并。它仍是带缓存的账号同步，不是严格取消本地持久化的纯云端客户端。

Compose 启用 `SERVER_IMAGE_ARCHIVE=true`：浏览器提交图片任务 → 186 调用本人配置的渠道（可经 New API）→ 生成结果持久化 → 186 归档 R2 → 任务完成。关闭网页不影响已接受的服务端任务；重新进入生图工作台可找回已归档任务，画布沿用原有任务恢复与账号同步。浏览器收到文件引用后不会重复上传。下载仍为 R2 → 186 鉴权代理 → 浏览器。

R2 不可用时任务停留在归档阶段，原始生成结果暂存 SQLite，后台每 30 秒检查并重试，不重新调用模型；远端临时图片下载成功后先保留字节，避免链接随后过期。多图保存逐张进度，GIF 按原字节保存。成功后任务中的 Data URL 被替换为文件引用；SQLite 空闲页会复用，文件体积未必立即缩小。已归档任务保留小型元数据供找回，图片生命周期沿用原生文件管理。

此改动覆盖图片任务，未扩展音频/视频归档。服务进程在模型请求返回前重启时，不能保证请求恢复；已返回并保存的结果支持后台恢复归档。未登录仍沿用浏览器直连及本地保存。

## 提示词库

采用 `basketikun/infinite-canvas` 同源的七套标准 JSON，来源为 `yukkcat/image-prompts` 的 `dist/sources`。后台“提示词管理”按分类同步更新，失败保留现有数据，保留作者及来源链接。不执行来源脚本，也不下载整个图片仓库。

SQLite 仅保存提示词文字、标签和图片 URL；卡片、详情图与首页功能轮播均由浏览器向原 GitHub/CDN 来源加载，不占用本站媒体盘或 R2。原来源失效时示例图可能不可用。用户选作参考图后的实际任务上传、个人上传和生成结果仍按本站存储流程处理。

初始化导入 1,742 条，文字、标签及链接约 2.8 MB；数据库索引、WAL 和备份另计。已通过七类真实同步、浏览器分类/搜索/复制/详情、外部示例图加载、完成图片任务恢复及两账号隔离检查。Go 测试覆盖断开浏览器后归档、存储故障重试、多图进度和双帧 GIF 原字节保存；真实 R2 后台归档/读取/删除使用测试图片验证，未调用收费模型。GIF 模型与 New API 全链路仍需实际验收。
